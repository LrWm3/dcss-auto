# Crawl experimental ledger

Historical audit: **2026-09-14**. This is the consolidated, adjudicated account of the autocrawl → tactical learning → general-policy project, not a claim that every experiment was reproducible or successful. It includes negative results, contaminated trials, infrastructure checks and unexecuted proposals.

## Start here

**Bottom line:** we built substantially better experimentation machinery and some effective local controllers. We have not yet demonstrated a reliable autonomous improvement in general-policy held-out game score. Local imitation, tactical training accuracy, small seed screens and plumbing success repeatedly looked better than subsequent generalization tests. The latest completed critic experiment changes prediction, not gameplay; its small apparent advantage is concentrated in one test game.

The useful evidence is split into four layers:

- This ledger: hypotheses, outcomes, qualifications and what superseded what.
- [Source inventory](history/SOURCES.md): section-level document index, all recorded batch versions, run/support directories, and the complete commit chronology.
- [Conversation index](history/SESSIONS.md): 288 abbreviated final-answer records from the three-session ancestor chain, with original JSONL line links. These are historical reports, not independent verification.
- [Machine-readable inventory](history/inventory.json): paths, document hashes, full commit IDs, session-prefix hashes/fork boundaries and shallow artifact metadata. [Rebuilder](history/build_inventory.py) regenerates the inventory, not this interpretation.

The original [progress journal](PROGRESS.md), [RC run records](runs.jsonl), [tactical documentation](tactical/README.md), [general-policy documentation](autonomous/README.md), and [archived-system explanation](archive) remain intact. The inventory deliberately includes unadjudicated and support directories: **a directory or `complete` status does not establish a successful experiment**.

## Interpretation and provenance rules

Prefer actual result files and verified replay evidence over journal summaries, commit titles or conversational conclusions. Where only a session report survives, this ledger says so. Implementation commits prove a change existed, not that it improved play. Recent experiments include uncommitted working-tree code; their artifact manifests and saved checkpoints are more precise provenance than the last Git commit alone.

Dates below follow journal/commit dates for early phases. Session timestamps are UTC and can cross into the following date. Character suffixes are not trial counts. “Reached” is not “cleared”; shafts caused several misleading deep-floor results. A resumed save with a new policy, or manual item use, is a diagnostic continuation—not an autonomous same-policy full-seed result. Repeating a deterministic seed tests reproducibility, not independent robustness.

Objectives also changed, so do not pool scores across the entire project:

1. Original RC: pause on red encounters; later red used yellow logic, with autonomous death or D15 clear as the operational endpoint.
2. Five-seed tuning: improve the **lowest reached progression rank**; Lair/Orc ranks are not Dungeon floor numbers.
3. Early tactical RL: proxy recovery and optional RC continuation; some apparent recoveries subsequently died.
4. Goal/action controllers: actual recovery, generally full health plus **20 quiet turns**. The discussed 100-turn wait was not the implemented standard.
5. General policy: native Crawl score, with administrative cutoffs eventually assigned their actual current score rather than automatically disqualified.
6. Later user-approved training objective: `training_score = 10*native_score + min(sum(100*effective_depth*revealed_fraction), 100 + 2*native_score)`. Native score is retained separately, and general promotion still uses native score. Combined training-score values must not be compared directly with earlier native-score values.

Seed siblings, character mutations, snapshots from one game and repeated action-sampling continuations are correlated. Opened/tuned test cohorts become regression evidence, not untouched tests. Failed simulator runs and missing outcomes must not silently become deaths, recoveries or zero-score games.

### Latest proposed experiment — not yet run

The latest review suggested returning to **paired counterfactual policy improvement**, with stronger safeguards: automatically capture about24 states; compare three plausible actions under several paired continuations; independently confirm winning actions before distillation; preserve incumbent behavior elsewhere; then evaluate full games on fresh seeds. Historical defaults included short8/12-step continuations and epsilon.15, whereas newer navigation/exploration experiments already used384-step continuations. **Longer action-ranking rollouts and conservative distillation have already been tried** (F09/F13/F14); the proposed novelty is better pairing, independent confirmation and uncertainty control, not their mere existence.

Research consulted in that review: [rollout policy iteration](https://arxiv.org/abs/0805.2027), [PEGASUS paired simulation scenarios](https://arxiv.org/abs/1301.3878), [imitation-learning scaling](https://arxiv.org/abs/2307.09423). These are historical research pointers, not evidence our next implementation will work. No new search or training was performed for this ledger.

## What the accumulated evidence says not to repeat blindly

- **Do not equate fitting labels with better play.** This failed for linear Q, goal selectors, directional BC, V6 bootstrap, preference ranking and PPO development screens.
- **Keep the simulator fidelity audit.** Resume greetings, console stepping, dumps and synthetic setup each altered RNG at different times. Repeatability after loading is weaker than fidelity to the original uninterrupted game.
- **Preserve legitimate outliers and report uncertainty.** V0's D7/1,065 replay was real. Dropping selected strong baseline seeds changes the question. More continuations improve estimates but do not become more independent seed families.
- **Protect against action-distribution collapse and navigation blindness.** WAIT oversampling, absent stairs, short history, missing visit features and omitted action-target entities were separately observed. A larger model alone does not repair missing inputs or biased labels.
- **Do not relearn only from successful/simple encounters.** Tactical pursuit ceilings and heavily D1-dominated general rollouts repeatedly hid harder decisions. Use correct endpoints and report failures/censoring explicitly.
- **Value prediction is not policy improvement.** The critic ablation has only seven usable test games and one dominating tail. Its small loss reduction is insufficient to justify changing the actor.
- **Reuse proven speed infrastructure.** FIFO, delay suppression, worker/cache parallelism, feature batching/caching and non-quitting snapshots already exist and were measured. Revalidate integration rather than re-presenting them as new ideas.
- **No guaranteed stronger champion has been established.** Running many cycles, adding features or passing smoke tests did not meet the boss's measurable held-out improvement condition.
